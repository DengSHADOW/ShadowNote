# 多智能体系统控制流劫持

多智能体系统控制流劫持（MAS hijacking）指攻击者通过 MAS 所处理的不可信外部输入，操纵智能体间传递的 metadata 或通信内容，从而把后续 action trace 改写为攻击者指定的调用序列。攻击目标是系统级 orchestration，而非单个模型的一次输出。（PDF p. 2–5，§1–4；PDF p. 19，附录 C）

> **英文原文：** “MAS hijacking exploits metadata transmission pathways to reroute the sequence of agent invocations.”（PDF p. 2，§1）

该攻击的典型路径是：前线 file 或 web agent 读取恶意内容后，向 orchestrator 返回貌似合理的错误或状态信息；orchestrator 据此调用 coder、executor 或其他高权限 agent。攻击者无需控制 agent，也无需直接提示 orchestrator。（PDF p. 4–5，§3–4）

> **英文原文：** “The adversary cannot directly prompt the MAS.”（PDF p. 5，§3.1）

形式上，论文将 MAS 表示为由 agent 集合与通信连接组成的有向图，并把攻击定义为使外部输入之后的 action trace 后缀包含攻击者指定动作的过程。（PDF p. 19，附录 C）

> **英文原文：** “The attack seeks to modify the action trace suffix.”（PDF p. 19，附录 C）

这一概念扩展了 [[agentic-harness|Agentic Harness]] 的安全边界：agent、工具、memory 与协调逻辑均可能共同决定危险 action 是否发生。它不同于 [[schema-fragility|工具调用智能体的模式脆弱性]]，后者关注 schema/意图失配；控制流劫持关注恶意 metadata 对协调路径的操纵。（PDF p. 4–5，§2–4）

> **英文对应表述（非逐字原文）：** The attack concerns malicious manipulation of orchestration through inter-agent metadata rather than a tool-schema mismatch.
