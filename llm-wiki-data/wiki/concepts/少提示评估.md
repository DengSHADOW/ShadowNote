# 少提示评估

少提示评估关注模型在 `N={1,2,3,5,9}` 个点条件下的 IoU，目标是衡量用户只提供少量输入时的可用性。它不同于传统交互式分割中允许最多约 20 个点、统计达到目标 IoU 所需交互次数的协议。（PDF pp. 19–21，§D.1）

> **英文对应表述（非逐字原文）：** The evaluation emphasizes mask quality after a small fixed number of point prompts rather than the number of interactions needed to reach a target IoU.

[[SAM]] 在 23 个数据集的单点默认结果中有 16 个优于 RITM；从 3 个候选 masks 中进行 oracle 选择时则在全部 23 个数据集上超过 RITM。这一区分把候选生成能力与 predicted-IoU 排序能力分开。（PDF pp. 7–8，§5.1；PDF pp. 19–21，§D.1）

> **英文对应表述（非逐字原文）：** Default one-point selection beats RITM on 16 datasets, whereas oracle selection among three candidates does so on all 23 datasets.

该协议有明确适用边界：作者预计在大量交互点条件下，针对高 IoU refinement 优化的专用交互式模型可能优于 SAM。因此，少提示优势不应外推为所有交互预算下的全面优势。（PDF pp. 19–21，§D.1）

> **英文对应表述（非逐字原文）：** The authors expect specialized interactive models to regain an advantage when many corrective clicks are available, so few-prompt performance should not be generalized to every interaction regime.

少提示评估与[[歧义感知多掩码预测]]共同构成对[[可提示分割]]的核心测量框架。
