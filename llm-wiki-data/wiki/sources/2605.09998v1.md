## 书目信息

Seth Karten、Joel Zhang、Tersoo Upaa Jr、Ruirong Feng、Wenzhe Li、Chengshuai Shi、Chi Jin 和 Kiran Vodrahalli 提出了 Continual Harness：一个面向 embodied agents 的在线适应框架。版本为 arXiv:2605.09998v1，手稿日期为 2026 年 5 月 12 日，作者单位包括 Princeton University、ARISE Foundation 和 Google DeepMind。

## 核心思想

[[continual-harness]] 将 [[agentic-harness]] 视为可变状态：

```text
Ht = (p, G, K, M)
```

其中 `p` 是 system prompt，`G` 是 sub-agents，`K` 是 skills，`M` 是 persistent memory。Warm-up `W` 之后，Refiner 每隔 `F` 步检查最近的 trajectory window，识别 failure signatures 并执行 CRUD 修改：

```text
st = (ot, mt)
at ∼ M(· | st, Ht, τt)
∆ = (∆p, ∆G, ∆K, ∆M)
Ht+1 ← Ht ⊕ ∆
```

Refiner 的四个连续过程会修订 prompt、管理 sub-agents、创建或修复 skills，并更新或降级 memory entries。修改发生在正在运行的 trajectory 内，不重置环境。

## 环境与接口

主要评测使用 Pokémon Red 和 Pokémon Emerald；[[Gemini-Plays-Pokemon]] 的 case studies 覆盖 Pokémon Blue、Yellow Legacy 和 Crystal。接口保持受限：

```text
Observation:
- rendered frame: 160×144 for Red/Crystal; 240×160 for Emerald
- image upscale: 2×
- ASCII local text map mt
- emulator advance per observation: 120 frames

Actions:
UP, DOWN, LEFT, RIGHT, A, B, START, SELECT

ASCII map symbols:
.  walkable tile
#  wall
?  interactable tile
N  NPC
```

Text map 描述局部可见区域，不提供 walkthrough、objective list、pathfinding 或 global map。不过它来自 emulator memory，作者明确以此补偿 vision-language models 的空间推理局限（Appendix A，PDF p. 14）。

## 主要结果

在 Pokémon Emerald 中，Gemini 3.1 Pro 驱动的 Continual Harness 从零开始达到 100% milestones，median API cost 为 $130。Minimalist harness 达到 98%，成本 $215，即以约 40% 更高成本换来略低 completion（Section 4.4、Figure 6、PDF pp. 7–8）。

结果强烈依赖模型能力。使用 Flash 时，bootstrap-updating 达到 80% completion、成本 $42；minimalist harness 为 77%、成本 $30。使用 Flash-Lite 时，minimalist harness 达到 20%、成本 $11，而所有 Continual Harness 变体只达到 3–13%，成本相近或更高。这支持 [[capability-floor]]，而非普遍收益。

Navigation skills 相对于 Dijkstra oracle 的评测显示：初始 path-cost deficit 约 50%，在早期下降至个位数百分比并保持。该测量只选取 evolved navigation skills 的前 10%，且 comparator 基于各 runs 观测到的 tiles 的并集，因此未衡量失败 skill 创建的全部成本（Section 4.6、Appendix C.1.1、PDF pp. 9、22）。

## Create-and-forget 行为

Skill 生成存在很长的未使用尾部：

| Condition | Created | Invoked ≥ 1 | Invoked ≥ 3 | Succeeded ≥ 1 |
|---|---:|---:|---:|---:|
| Emerald phase 1 | 99 | 17 (783 invocations) | 11 | 5 (304 successful) |
| Red phase 1 | 110 | 33 (487 invocations) | 18 | 3 (247 successful) |
| Emerald phase 2 cont. | 104 | 16 (364 invocations) | 11 | 5 (73 successful) |
| Red phase 2 cont. | 335 | 53 (720 invocations) | 31 | 14 (380 successful) |

Figure 16 表明 refinement 过程主要修复频繁使用的小型 working set，并未形成整体整洁的 skill library。参见 [[create-and-forget-skill-funnel]]。

## Harness 的迁移

跨 run 迁移只有在 agent 继续使用 inherited components 时才有效：

| Game | Store | Frozen | Continued |
|---|---|---:|---:|
| Emerald | skills | 100.0% ± 0.0 | 99.6% ± 0.6 |
| Emerald | subagents | 100.0% ± 0.0 | 100.0% ± 0.0 |
| Emerald | memories | 98.2% ± 1.9 | 100.0% ± 0.0 |
| Red | skills | 100.0% ± 0.0 | 96.5% ± 3.8 |
| Red | subagents | 100.0% ± 0.0 | 6.4% ± 5.7 |
| Red | memories | 100.0% ± 0.0 | 100.0% ± 0.0 |

在 Red bootstrap-updating 中，inherited sub-agents 的使用率跌至 6.4% ± 5.7，milestone progression 也恶化。因此 harness 的可迁移性需要合适的 reuse policy，不能只依赖 components 的存储（Appendix C.2，PDF pp. 24–25）。

## Model–harness co-learning

该工作把 refinement 扩展到 [[Gemma-4]] student 的 weights。每个 iteration 包含 256-step rollout、PRM scoring、由 Gemini-3.1-pro 对低 reward windows 进行 relabeling，以及 soft SFT：

```text
R(st, at, τ) ∈ [0, 1]
θk+1 = θk − η∇LSFT
```

Figure 7 展示五个有进步的 runs：从 early 或 mid-game checkpoints 分别增加 2–6 个 milestones。Untrained baseline 未超过初始 milestone。由于只报告了 advancing runs，未报告 jobs 总数，该结果不能给出 success rate，并可能受 selection bias 影响。

### Training 设置

```text
Supervised fine-tuning
- Models: Gemma-4 E2B, E4B, 26B MoE, 31B dense
- LoRA rank: r=256
- LoRA α: 256
- Precision: bf16
- Context: 8K tokens
- Library: Unsloth
- Hardware: H200 GPUs
- Learning rate: 2 × 10−5
- Linear warmup: 3%
- Schedule: cosine decay
- Training passes: 1

Offline GRPO
- Samples per state: G=4
- Action correctness weight: 0.6
- Format compliance weight: 0.4
- Learning rate: 1 × 10−6
- KL coefficient: β=0.04
- Batch size: 8 states
- Optimization steps: 590

Online co-learning
- Rollout length: K=256
- PRM trajectory progress weight: 0.4
- PRM action correctness weight: 0.3
- PRM reasoning quality weight: 0.2
- PRM format compliance weight: 0.1
- Soft SFT: 3 epochs
- Learning rate: 5×10−6
- Pairwise PRM stride: 8
- Teacher: Gemini-3.1-pro
```

Warm-up 阶段主要改善 format compliance 和部分 action-quality 指标，单独并未产生实质 milestone progression。

## 具体 failure mode

在 Power Plant case study 中，GPP 创建了 `fly_menu_navigator`，但没有遵循所需的 tool-call schema。它应输出 `buttons_to_press: ["tool"]`，却输出 `["Down"]`，导致本应发生的工具调用没有执行。Agent 在一个持续 1,003 turns 的 stall 中重复相同 payload 842 次，同时其内部推理声称正在检验假设。该案例把 [[schema-fragility]] 与 feedback blindness 联系起来，说明语言层面的自我评估不保证行为修正（Appendix B.3，PDF pp. 16–21）。

## 局限

- 主要实验只覆盖同一系列的两款游戏。
- 没有在相同条件下对 reset-free 与 reset-based training 做 head-to-head 比较。
- Co-learning 依赖 frontier teacher 和独立 PRM，并非完全自主。
- 未证明 convergence 或 asymptotic superiority。
- Memory 在成熟且 inherited 时更有作用；from-scratch runs 中许多 entries 仍未被使用。
- “GPP 是首个完成多款 Pokémon RPG 的 AI system”是作者声称，未由该来源独立验证。
- 没有 robotics、coding 或 production operations 的实证结果。

## 内部不一致

Section D.2 将 Gemma-4 31B SFT 描述为可行的 Red checkpoint，并称其用作 initial policy；Section D.4 却称 online experiment 从 Gemma-4 26B SFT 开始，尽管 26B Red adapter 曾被描述为 degenerate。

此外，Section 4.3 称 Red bootstrap-updating 在每个 milestone 上都比 from-scratch 更有效；Appendix C.2 则描述它后来低于 from-scratch，随后又低于 minimalist harness。来源未充分说明这些说法是否对应不同 phases 或不同可视化。
