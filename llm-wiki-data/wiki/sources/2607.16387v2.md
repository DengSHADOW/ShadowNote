# Fantastic Adaptive Taxonomies and How to Use Them

> 本页由 LLM Wiki 自动分析结果翻译修复而来，已保留原有数字、表格、限制和 PDF 页序号。页面状态仍为 draft；重要结论用于 review 前应继续回查原 PDF。

## 全局综合分析

### 总结

AdaMAST 从执行轨迹中归纳自适应失败分类体系，并将其复用于搜索、运行时监控和轨迹选择。该分类体系提供持久、目标特定的反馈，其中 A 轴表示系统级代码，B 轴表示角色或阶段特定代码，C 轴表示领域推理代码。结果支持其在推理搜索、软件工程运行时 harness 和基于文档的定量推理中带来收益，但不同设置下的证据强度并不相同。

### 实体

- **AdaMAST**、**AdaMAST-Judge**、**MAST**、**AdaEvolve**、**TRAIL**。
- **Claude Code**、**SWE-agent**、**ForgeCode**、**terminus-2**、**GPT-5**、**Claude Haiku 4.5**。
- **Frontier-CS**、**OlympiadBench**、**MMLU-Pro**、**TheoremQA**、**DROP**、**SWE-bench Verified Mini**、**Terminal-Bench 2.0**、**OfficeQA Pro**。
- 来源：“Fantastic Adaptive Taxonomies and How to Use Them”，arXiv:2607.16387v2，2026-07-29。

### 概念

- **自适应失败分类体系（adaptive failure taxonomy）：** 从执行轨迹中得到的、面向特定目标的具名失败代码目录。
- **三轴框架（three-axis scaffold）：** A 表示系统级失败，B 表示角色或阶段特定失败，C 表示领域推理失败。
- **分类体系条件化消费组件（taxonomy-conditioned consumer）：** 接收触发代码和轨迹证据的搜索、运行时或选择组件。
- **在线优化（online refinement）：** 架构或分布变化后，对代码进行合并、添加、停用或重新标记。
- **可操作的验证标准（actionable verification criterion）：** 可用于验证轨迹的归纳代码。
- **失败压缩（failure compression）：** 对更大轨迹池的紧凑表示。
- **阶段特定分类体系（phase-specific taxonomy）：** 针对单智能体系统，将 B 轴适配到 `Edit`、`Plan`、`Verify` 阶段。
- **可靠解决转化（reliable-resolution conversion）：** 将 Base 偶尔成功的实例转化为 AdaMAST 稳定成功的实例。
- **注入位置与格式无显著影响结果：** 反馈位置可能影响性能；类别化形式本身并未被证明优于内容等价的自然语言表述。

### 主要论断

- 自适应分类体系可以作为自我改进智能体的持久反馈接口。
- 在报告的五个推理 benchmark 上，AdaMAST 引导的搜索优于 LLM Guidance。
- AdaMAST 运行时反馈提高了 Claude Code 和 SWE-agent 的性能。
- AdaMAST-Judge 提高了 Terminal-Bench 2.0 上的 best-of-5 选择准确率。
- 具体代码会随领域和架构而适配：扁平架构可能没有 B 类代码，单智能体的阶段行为则会产生 `Edit`、`Plan`、`Verify` 代码。
- 在 Claude Code/SWE-bench 中，AdaMAST 的改进主要体现为提高原本偶尔可解实例的可靠性，而不是使全新的实例从根本上变得可解。
- 在 OfficeQA Pro 中，AdaMAST 给出了积极的跨领域结果，但不足以单独估计平均效应。
- 当 judge/轨迹内容保持不变时，类别化表达没有被明确证明优于自然语言表达。

### 证据

- 搜索：Frontier-CS 上 AdaMAST 32.7%，LLM Guidance 26.0%；OlympiadBench 为 91.9% 对 87.9%；MMLU-Pro 为 42.5% 对 35.0%；TheoremQA 为 65.0% 对 60.0%；DROP 为 91.7% 对 88.2%。
- 运行时：Claude Code 上 AdaMAST 为 70.7%，Base 为 64.0%，MAST 为 67.3%；SWE-agent 上分别为 70%、50%、68%，Reflexion 为 60%。
- 选择：AdaMAST-Judge 在 terminus-2、claude-code 和 ForgeCode 上分别达到 73.0%、72.4%、89.9%。
- TRAIL：在匹配的标注协议下，归纳词表达到 κ=0.682，手工词表为 κ=0.516；完整协议达到 κ=0.725。
- 压缩：223 条运行时轨迹约实现 18× 压缩，且 89% 为唯一签名。
- OlympiadBench 初始分类体系：36 个代码（16A/6B/14C），其中 `Instruction_Compliance_Violation` 的触发率为 100%。
- SWE-agent 的 SWE-bench 分类体系：30 个代码（8A/11B/11C），其中 `Ad hoc validation only` 为 90%，`Misread root cause` 为 82%。
- Claude Code/SWE-bench：在单种子触发计数运行中，AdaMAST 解决 35/50，Base 为 30/50，MAST 为 34/50；在全部三个种子下稳定解决的实例数，AdaMAST 为 28，Base 为 27。
- OfficeQA Pro：AdaMAST 的严格准确率为 51.9%（69/133），control 为 44.4%（59/133）；McNemar `p ≈ 0.10`。
- TheoremQA：将反馈附加到评估结果为 63.3%，内联代码注释为 53.3%，系统消息为 46.7%。
- TheoremQA 反馈格式：结构化代码、自然语言摘要、原始轨迹摘录的搜索后平均准确率分别为 56.7%、61.1%、56.7%。

### 矛盾与限定

- 选择性能同时依赖选择器和验证器机制，不能只归因于分类体系质量。
- MAST 在部分运行时设置中达到相同性能。
- 触发频率不能证明某个代码对架构改进或任务成功具有因果贡献。
- Claude Code 中最常见的 B 类代码 `B.7` 触发范围很广，但失败预测能力较弱；不太常见的 `B.3` 反而是更强的预测指标。
- Claude Code 上的 AdaMAST 改进不能作为基础能力边界扩展的证据。
- 在小规模反馈格式诊断中，自然语言摘要的数值高于结构化代码，但作者将差异归因于随机种子噪声，不能据此建立自然语言表达普遍更优的结论。

## 分块分析

### Chunk 1/3 — PDF p. 1

- “Fantastic Adaptive Taxonomies and How to Use Them”提出 AdaMAST：一种从执行轨迹中归纳紧凑、有证据依据且面向特定智能体系统的失败分类体系的流程。
- 分类体系具有三个固定干预轴：A 为系统级，B 为角色特定，C 为领域特定。具体代码、定义、角色标签和证据模式由轨迹生成，无需手写代码或逐条轨迹人工标注。
- 开发流程包括 ANALYSIS、CURATION、CONSOLIDATION 和 INTER-ANNOTATOR AGREEMENT。只有当四个 LLM 标注器在失败区域层面的平均两两 Cohen’s κ ≥ 0.75，且覆盖率 ≥ 0.70 时，分类体系才会部署。
- 同一分类体系被用作以下反馈接口：AdaEvolve 智能体系统搜索、Claude Code/SWE-agent 运行时监控，以及 AdaMAST-Judge 的 best-of-N 轨迹选择。
- 新增或更新的实体：AdaMAST、AdaMAST-Judge、MAST、AdaEvolve、TRAIL、Frontier-CS、OlympiadBench、SWE-bench Verified Mini、Terminal-Bench 2.0、Claude Code、SWE-agent、ForgeCode、TheoremQA、DROP、MMLU-Pro、OfficeQA Pro。
- 新增或更新的概念：自适应失败分类体系、分类体系条件化消费组件、在线优化、失败代码、失败区域一致性、运行时检查点、分类体系引导的轨迹选择、角色特定失败、领域特定失败、压缩失败表示。
- 建议的来源页类型：`arXiv:2607.16387v2` 学术论文。

#### 发现与证据

- 作者报告 AdaMAST 在五个搜索 benchmark 上比自由形式反思高 3.5–7.5 个百分点。
- 在 SWE-bench Verified Mini 中，Claude Code 从 64.0% 提高到 70.7%，SWE-agent 从 50% 提高到 70%；后者超过 Reflexion（60%）和 MAST（68%）。
- 在 Terminal-Bench 2.0 中，AdaMAST-Judge 的 best-of-5 相比 Pass@1 提高 8.1–14.9 个百分点。
- 在 TRAIL 中，匹配标注协议下，归纳词表达到区域级 κ=0.682，而手工 TRAIL 分类体系为 κ=0.516；加入 span grounding 和 deliberation 后达到 κ=0.725。
- 六个领域分类体系的平均两两 Jaccard 为 0.14，支持具体代码具有系统/领域特定性；映射到通用 backbone 后，重叠率上升到 0.50。
- 在 223 条 SWE-bench 轨迹中，作者测得约 18× 压缩，每条轨迹触发代码数的中位数为 5，且 89% 是唯一代码签名。
- 限定：不同运行时 harness 属于独立案例研究，不是受控的相互比较；AdaMAST-Judge 的收益也同时依赖分类体系和学习得到的选择器/验证器底层机制。

### Chunk 3/3 — PDF p. 37

- **总结：** 在 Claude Code/SWE-bench 中，AdaMAST 主要把不稳定解决转化为可靠解决，并未开启全新的可解实例类别。在 OfficeQA Pro 中，同一分类体系条件化检查点流程带来积极但证据有限的跨领域改进。消融结果表明反馈注入位置很重要，而代码的类别化形式并未明确优于内容等价的自然语言表述。
- **新增或更新的实体：** **OfficeQA Pro**、**GPT-5**、**Claude Haiku 4.5**、**django**、**sphinx**、**TheoremQA**。
- **新增或更新的概念：**
  - **阶段特定分类体系：** 针对单智能体 harness，将 B 类代码适配到 `Edit`、`Plan`、`Verify` 阶段。
  - **可靠解决转化：** 将 Base 偶尔成功转化为稳定成功的改进。
  - **注入位置：** 将诊断结果加入变异提示词的位置。
  - **格式无显著影响结果：** 当 judge/轨迹内容不变时，类别化形式与自然语言或原始摘录之间没有清晰差异。
- **论断、发现和证据：**
  - 在 150 个已评判的 Claude Code 会话中，`B.7 Verify partial run misreported as success` 经常出现（40.7%），但只是较弱的失败预测指标：61 次触发中有 25 次未解决（41%），背景未解决率为 34%。
  - `B.3 Edit overbroad patch footprint` 较少出现（8.0%），但预测能力很强：12 次触发中有 11 次未解决（92%）。
  - AdaMAST 运行时 skill 在三个种子下都解决了 28 个实例，而 Base 为 27 个。不存在某个实例在所有 AdaMAST 种子下都能解决、却在所有 Base 种子下均不能解决；收益体现为可靠性，而不是新的能力边界。
  - 在 OfficeQA Pro 中，AdaMAST 将严格准确率从 44.4%（59/133）提高到 51.9%（69/133）。配对结果为：仅 AdaMAST 成功 20 个，仅 control 成功 10 个，两者都成功 49 个，两者都失败 54 个；双侧精确 McNemar `p ≈ 0.10`。
  - 在 TheoremQA 注入位置消融中，把诊断附加到评估结果达到 63.3%，内联注释为 53.3%，系统消息为 46.7%。
  - 在反馈形式诊断中，自然语言摘要的平均值为 61.1%，结构化 AdaMAST 代码和原始轨迹摘录均为 56.7%。作者称其为小样本的“格式无显著影响”结果，而不是核心论断。
